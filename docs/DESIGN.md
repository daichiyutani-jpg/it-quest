# 学習の判定と自動調整の設計（学習アプリ共通ルール §7・§9〜§13）

作成：2026-11-06（0.3.0）。コードと数値は一致させる。変えるときはここも直し、`tests/core.test.mjs` を通す。

## 1. 単元の理解度（`src/core/mastery.js` `unitStatus`）

| 段階 | 条件 |
|---|---|
| 未学習 | 説明を開いていない・問題も解いていない |
| 学習中 | 上と下のどれでもない |
| 要復習 | 直近6問の正答率 < 60%（3問以上解いたとき）、または間違えたままの問題が2問以上、または **最後の小テストが不合格** |
| 基礎理解済み | 説明を最後まで読んだ ＋ **小テスト（10問）に9問以上で合格**（最後のテストが不合格でない） |
| 習得確認済み | 基礎理解済み ＋ **時間を空けた再確認**：最初に合格した日から2日以上あとに、合格したテストに入っていない問題を3問以上解いて正答率80%以上（または2日以上あとに別の小テストにもう一度合格）＋ 直近の正答率80%以上 ＋ 間違えたままの問題なし |

基礎理解済み・習得確認済みでも、復習予定を7日以上過ぎた問題があれば要復習に戻す。
同じ問題に正解しただけでは上がらない（別の問題・時間を空けた再テストを合わせて判定。共通ルール §9）。
回答時間は理解度の判定に使わない（記録はする。§7）。

## 2. 小テスト（§10、`pickUnitTest`・`recordTest`・`renderTestResult`）

- 10問、1問ずつ。回答後は ⭕/❌ だけを表示し、正解・解説は出さない。
- 10問の後に、間違えた問題を先に（開いた状態で）解説、正解した問題は閉じた状態で並べる。自信のなかった正解の数も出す。
- 合格：10問中9問以上（90%）。照合済みの問題が10問に満たない単元では合否を出さない。
- 不合格：「間違えた所を復習する」（要点・用語・図解・具体例を読み直して、間違えた問題を中心に5問）→「別の問題で再テスト」。
- 問題の選び方：①これまでの小テストに出していない・練習でも解いていない問題 → ②小テストに出していない問題 → ③（出し切ったら）前回以外のテストで出した問題 → ④前回の問題。1単元20問以上あるので、1回目と2回目は必ず別の問題になる（テストで確認）。
- 教材の中の練習問題（3問）は、間違えた時点で解説する。小テスト用の問題を残すため、すでに解いた問題を先に使う。

## 3. 復習の間隔（§11、`recordAnswer`）

箱（0〜5）と間隔（日）：`INTERVALS = [0, 1, 3, 7, 16, 35]`

| 回答 | 箱 | 次の復習まで |
|---|---|---|
| 不正解 | 1 | 1日。復習リストに入れる |
| 正解・自信あり | +1 | INTERVALS[箱] |
| 正解・たぶん | +1 | INTERVALS[箱] の半分（切り上げ、最低1日） |
| 正解・勘 | 1のまま | 1日。復習リストに入れる（自信のない正解を優先して確認） |
| この問題を2回以上間違えている（箱4未満） | — | 上の間隔をさらに半分（繰り返し間違える所の頻度を上げる） |

- 復習で出す順：未解決の間違い → 自信のない正解（勘・たぶん）→ 予定日を過ぎた日数が多い → 箱が小さい（`picker.js` `seenOrder`）。
- 安定して正解できる問題は箱が上がり、間隔が延びる（最大35日）。
- 時間を空けた再テスト＝上の「習得確認」の条件。

## 4. 間違えたときの対応（§9）

- その場で解説（正解の理由・選択肢ごとの理由）。
- 「別の説明で確かめる」：図解・具体例・やさしい説明・用語の意味を切り替えて表示（`quiz.js` `altExplain`）。見た形式を単元ごとに記録し、1時間以内に同じ単元の問題に答えたら、その回答に `after`（形式）を付ける。学習記録の「説明の形式と理解度」で形式ごとの正答率を出す。
- 間違えた理由を選べる（用語を知らなかった／2択まで絞れた／読み違え／計算ミス／なんとなく／似た用語と混同）。問題の `tags`（誤りやすさの種類）と合わせて「間違いの傾向」に集計。
- 理解が不十分な単元（要復習、または説明を読んだのに直近の正答率70%未満）は、新しい単元より先に「補強」を計画に入れる（`planner.js` `stuck`）。
- 前提知識：`src/data/prereq.js` の単元が未学習なら「先にこちらがおすすめ」と出す（強制しない。§8）。

## 5. 学習計画（§12、`src/core/planner.js`）

- 1日120分が初期値（本人が変えられる）。30日計画の開始日 `planStart` から30日目までが学習期間、目標日＝30日目。
- 開始日は「学習開始前の品質確認」がすべて済むまで設定できない（`readiness.js`。§16）。
- 模擬試験は31日目以降だけ計画に入れる（`mockOk`）。30日以内に受験日が来る設定なら、模擬試験の期間を取れないことを表示する。
- 直近14日の実際の学習時間で見込みを補正する（実績3日分から、10日で完全に反映）。遅れたら、重要度・理解度・苦手で順番を付け、後回しの単元を一覧で示す（省略しない）。
- 必要時間の見積りは docs/ESTIMATE.md。60時間を超える見込みなら根拠とともに表示する。
- 初回の基礎の確認（10問：S4・M2・T4、基礎の問題、中分類が重ならない。とばせる）の結果で、知識の目安（9問以上→「仕事で使っている」、6〜8問→「少し分かる」、5問以下→「ほぼ初めて」）と、正答率がいちばん低い分野の重要単元を開始点としておすすめする。使うかどうかは本人が選ぶ。

## 6. 合格の目安（§13、`src/core/judge.js`）

分野ごとに次を出し、判定する（ITパスポートは分野別にも合格基準があるため）。

| 指標 | 意味 |
|---|---|
| 範囲 | 重要度（★）で重みを付けた、小テスト合格（基礎理解済み以上）の単元の割合 |
| 初見 | 初めて解いた問題の正答率（分野で20問以上あるとき） |
| 本番形式 | 直近2回の模擬試験（20問以上）・公式の過去問（本番形式）の分野別正答率（分野で15問以上あるとき） |
| 定着 | 合格した単元のうち、時間を空けた再確認まで済んだ割合 |
| 要復習 | 要復習の単元の数 |

| 判定 | 条件 |
|---|---|
| 目安に届いている | 範囲90%以上・初見70%以上・本番形式70%以上・定着60%以上・要復習1単元以下 |
| あと少し | 範囲60%以上・初見60%以上・本番形式60%以上（本番形式がまだ無ければ、範囲と初見だけで「あと少し」まで） |
| まだ届いていない | 上のどれにも当たらない |
| 判定の材料が足りない | 初見も本番形式も足りない |

- 総合は3分野のうちいちばん低い判定（1分野でも届いていなければ届いていない）。
- 合格基準は総合600点・各分野300点（各1,000点満点）だが、IRT方式で評価点は正答率と一致しないため、正答率の目安は高め（70%）に置いた。この値は本アプリの判断で、IPAの公表値ではない。
- 「全単元の説明を読んだ」「全単元の小テストに合格」は、合格の目安とは別に表示する。
- 合格を保証しない。％の合格確率は出さない。

## 7. 記録するもの（§7）

学習時間（操作が2分ないと止まる）／教材の進捗（ページ）／問題ごとの正誤・選んだ選択肢・自信・回答時間／間違えた理由／単元ごとの理解度／形式別（用語・計算・事例）の成績／直前に見た別形式の説明／小テストの記録／模擬試験・公式の過去問の成績／復習予定。
保存形式の版は `meta.schema`（現在2）。v1→v2 の移行は `store.js` `migrate`、テストあり。
