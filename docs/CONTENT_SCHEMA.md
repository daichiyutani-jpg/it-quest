# 教材・問題データの書き方（IT QUEST）

教材と問題は `src/data/content/c1.js` 〜 `c5.js` に、単元ごとに書きます。プログラム本体とは分かれているので、ここを直すだけで内容を増やせます。
書いたら `node tools/validate.mjs` で形式チェックをしてください。

## 1単元の形

```js
export default [
  {
    unit: 'U01',                       // src/data/syllabus.js の単元ID
    lesson: {
      pages: [                         // 1. 学習テーマの説明（2〜4ページ。1ページ200字程度まで）
        { title: '会社は何のためにある？', body: '本文……' },
      ],
      terms: [                         // 2. 重要用語（5〜10語）
        { term: 'PDCA', read: 'ピーディーシーエー', desc: '計画→実行→評価→改善を繰り返す考え方。', item: 'U01-2' },
      ],
      example: '具体例（仕事や日常に結び付けた例。300字程度まで）',   // 3. 具体例
      beginner: '初学者向けの補足（つまずきやすい点・覚え方。250字程度まで）', // 4. 初学者向けの補足
      points: ['試験で問われやすい点', '…'],                         // 2〜4個
    },
    questions: [                       // 5. 確認問題（単元ごとに6問以上。シラバス項目をできるだけ全部カバー）
      {
        id: 'U01-q01',                 // 単元ID-q連番（全体で重複しない）
        item: 'U01-2',                 // 対応するシラバス項目ID
        type: 'original',              // original=オリジナル学習問題 / applied=応用問題（事例・複数知識）
        format: 'term',                // term=用語・知識 / calc=計算 / case=事例・文章読解
        level: 1,                      // 難易度 1=基礎 2=標準 3=やや難
        q: '問題文',
        choices: ['選択肢ア', '選択肢イ', '選択肢ウ', '選択肢エ'], // 必ず4つ。「ア」などの記号は付けない
        answer: 2,                     // 正解の位置 0〜3
        explain: '正解の理由',          // 6. 正解と解説
        why: ['アが誤りの理由', 'イが誤りの理由', 'ウが正解の理由', 'エが誤りの理由'], // 選択肢ごと。4つ
      },
    ],
  },
];
```

## 問題の区分（`type`）
| 値 | 表示 | 意味 |
|---|---|---|
| `official` | 公式公開問題 | IPAが公開した問題。`source: { year, season, number, url }` が必須。出典を確認できないものは使わない |
| `original` | オリジナル学習問題 | 本アプリ用に作った問題 |
| `applied` | 応用問題 | 本アプリ用に作った、事例や複数の知識を組み合わせる問題 |
| `mock` | 模擬試験問題 | 本アプリ用に作った模擬試験専用の問題 |

現時点で `official` は0問です（実物を確認できない問題を「公式過去問」と表示しないため）。

## ルール
- 実際の試験問題を写さない。オリジナルで作る。
- 正解は1つだけになるようにする。`explain` と `why[answer]` は正解と矛盾しないこと。
- 法律名は現行のもの（例：2026年1月から「下請法」→「中小受託取引適正化法」、2025年4月から「プロバイダ責任制限法」→「情報流通プラットフォーム対処法」）。
- 正解の位置（0〜3）は偏らせない。
- 問題数を水増ししない（同じ問題の言い換えを増やさない）。
