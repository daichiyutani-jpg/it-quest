# 教材・問題データの書き方（IT QUEST）

教材と問題は `src/data/content/*.js` に、単元ごとに書きます。プログラム本体とは分かれているので、ここを直すだけで内容を増やせます。
書いたら `node tools/validate.mjs` で形式チェックをしてください。

学習アプリ共通ルール（`~/.claude/learning-apps/RULES.md`）§15 により、**通常の学習に出すのは `status: 'verified'` のものだけ**です。作った直後は必ず `needs_review` にし、作成とは別の担当が出典と照合してから `verified` にします（照合結果は `src/data/verify/*.json` と `docs/FACTCHECK.md`）。

## ファイル

| ファイル | 中身 |
|---|---|
| `c1〜c5.js` | 教材（lesson）と問題（初版） |
| `c6a〜c6c.js` | よく出る単元の追加問題 |
| `c7a〜c7f.js` | 小テスト2回分（1単元20問以上）にするための追加問題と、図解（figures） |

同じ単元が複数ファイルに出てきてもかまいません（問題は足し合わせ、`lesson` は最初のもの、`figures` は足し合わせ）。

## 1単元の形

```js
export default [
  {
    unit: 'U01',                       // src/data/syllabus.js の単元ID
    lesson: {                          // c1〜c5 のみ
      pages: [{ title: '見出し', body: '本文……' }],
      terms: [{ term: 'PDCA', read: 'ピーディーシーエー', desc: '説明', item: 'U01-2' }],
      example: '具体例',
      beginner: '初学者向けの補足',
      points: ['試験で問われやすい点'],
    },
    figures: [ /* 図解・アニメーション（下記）。c7 で追加 */ ],
    questions: [
      {
        id: 'U01-q01',                 // 単元ID-q連番（全体で重複しない。c7 で足す問題は U01-q31 のように既存の最大番号の続き）
        item: 'U01-2',                 // 対応するシラバス項目ID（syllabus.js の items[].id）
        type: 'original',              // original / applied（事例・複数知識）/ mock（模擬試験専用）
        format: 'term',                // term=用語・知識 / calc=計算 / case=事例・文章読解
        level: 1,                      // 1=基礎 2=標準 3=やや難
        q: '問題文',
        choices: ['ア', 'イ', 'ウ', 'エ'], // 必ず4つ。記号は付けない
        answer: 2,                     // 正解の位置 0〜3
        explain: '正解の理由',
        why: ['アの理由', 'イの理由', 'ウの理由', 'エの理由'], // 選択肢ごと。4つ
        tags: ['mix'],                 // 任意。誤りやすさの種類（下記）
        sourceIds: ['SRC-001'],        // 出典ID（src/data/sources.js）。最低でもシラバス SRC-001
        status: 'needs_review',        // 作成直後は必ず needs_review
      },
    ],
  },
];
```

`status` と `sourceIds` は、照合結果ファイル（`src/data/verify/*.json`）の値で上書きされます。データファイル側を書き換えなくても、照合結果を置けば反映されます。

### tags（誤りやすさの種類。任意・複数可）
`mix`（似た用語と混同しやすい）／`calc`（計算・手順）／`read`（読み違えやすい）／`law`（法律の要件）／`order`（順序・手順）／`number`（数値の暗記）

## 図解・アニメーション（figures）

画像ファイルは使わず、データからSVGを描きます（`src/ui/figure.js`）。各図は「コマ」に分かれ、▶再生・⏸一時停止・コマ送り・最初からができます（動きを減らす設定の端末では自動再生しません）。
**図の中身（用語・順序・向き・数値）も問題と同じく照合の対象**です。

共通の項目：

```js
{
  id: 'U01-f1',        // 単元ID-f連番
  type: 'flow',        // 下の6種類
  title: '図の題名',
  caption: '図の下に出す1〜2文の説明',
  item: 'U01-2',       // 対応するシラバス項目ID
  sourceIds: ['SRC-001'],
  status: 'needs_review',
  // 以下、type ごとの項目
}
```

| type | 用途 | 項目 | コマの進み方 |
|---|---|---|---|
| `flow` | 手順・流れ（左→右、または上→下） | `nodes: [{ label, note? }]`（2〜7個）、`dir: 'h'|'v'`（省略時 v） | 1コマ1ノード |
| `cycle` | 繰り返し（PDCA など） | `nodes: [{ label, note? }]`（3〜6個） | 1コマ1ノード |
| `layers` | 階層・積み重ね（上から順） | `rows: [{ label, note? }]`（2〜8段） | 1コマ1段 |
| `compare` | 比較表 | `cols: ['観点', 'A', 'B']`、`rows: [['速さ', '速い', '遅い'], …]`（2〜6行・2〜4列） | 1コマ1行 |
| `steps` | 計算・解き方の段階 | `steps: [{ text, expr? }]`（2〜7段。expr は式） | 1コマ1段 |
| `tree` | 分類・構造 | `root: '名前'`、`children: [{ label, children?: [{ label }] }]`（子2〜5、孫は各0〜4） | 1コマ1つの子（とその孫） |

- `label` は12字程度まで、`note` は30字程度まで（スマホ幅で読める長さ）。
- 1単元に1〜2個。その単元で一番「文字だけでは分かりにくい」ところを図にする。装飾目的の図は作らない。
- 計算問題がある単元は、`steps` で解き方の図を1つ入れる。

## 問題の区分（`type`）
| 値 | 表示 | 意味 |
|---|---|---|
| `original` | オリジナル学習問題 | 本アプリ用に作った問題 |
| `applied` | 応用問題 | 本アプリ用に作った、事例や複数の知識を組み合わせる問題 |
| `mock` | 模擬試験問題 | 本アプリ用に作った模擬試験専用の問題 |

IPAの公開問題は問題文をアプリに入れず、利用者がPDFを取り込む方式（`#/past`、`src/data/past.js`）です。

## ルール
- 実際の試験問題・市販教材を写さない。オリジナルで作る。
- 正解は1つだけ。`explain` と `why[answer]` は正解と矛盾しないこと。
- 同じ単元の既存問題と同じことを言い換えただけの問題を作らない（小テストの再テストで「別の問題」にならないため）。
- 法律名は現行のもの（例：2026年1月から「下請法」→「中小受託取引適正化法」、2025年4月から「プロバイダ責任制限法」→「情報流通プラットフォーム対処法」）。
- 正解の位置（0〜3）は偏らせない。
- 問題数を水増ししない。
