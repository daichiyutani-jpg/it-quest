# 公式情報の確認履歴・教材の更新履歴（学習アプリ共通ルール §14）

## 更新の手順（開発側の作業）

1. 公式情報を取得する（SRC-001〜SRC-003 のページ・PDF）。
2. 前回の内容と比べる（シラバスはPDFの SHA-256 と改訂履歴、試験要項は数値）。
3. 変わった箇所を特定する。
4. 影響する単元・問題・図・教材を `src/data/syllabus.js` の項目IDから特定する。
5. 教材を直す（`src/data/content/`）。
6. 公式情報と照合する（作成とは別の担当。docs/FACTCHECK.md）。
7. 直した問題・正解・解説を再検証する（`node tools/validate.mjs`、`node --test tests/*.test.mjs`）。
8. 照合済みのものだけを反映する（`node tools/merge-verify.mjs` → `node tools/build-sw.mjs` → 公開。公開は本人の承認後）。
9. この表に確認日時と結果を書く。

- アプリは公式情報の正しさを自分で確かめられないので、端末の中で教材を書き換えることはしない。オンライン時に、公開済みの照合済み教材を Service Worker が取り込む（次に開いたとき反映）。アプリを閉じている間は更新されない。
- 不正確になったおそれがある教材・問題は、照合結果で `suspended` にする（出題を止め、「データ」画面に一覧を出す）。
- 公式ページの変更検知の自動化（例：公開リポジトリの GitHub Actions でページのハッシュを比べるだけ）は、無料の範囲でも**導入前に本人の承認が必要**。未導入。
